The three tab folders are gone. What made that safe was not the migration map
below on its own — it was checking it. A sweep for components and routes with
zero remaining references found nine orphans, five of which the flattening had
created, and two routes (`/people`, `/badges`) with no link anywhere in the app.
Every one is re-homed above. **A migration map is a plan; the orphan sweep is
the evidence.** Re-run it after any future navigation change:

```sh
# components nothing imports
for f in $(find components -name '*.tsx' | sort); do
  b=$(basename "$f" .tsx)
  n=$(grep -rl "from '.*/${b}'\|from '\./${b}'\|from '\.\./${b}'" \
        --include=*.tsx --include=*.ts app components store hooks lib \
      | grep -v "^$f$" | grep -v __tests__ | wc -l)
  [ "$n" -eq 0 ] && echo "ORPHAN: $f"
done

# routes nothing pushes to
grep -rn "'/people\|'/badges\|'/tickets" --include=*.tsx app components | grep -v __tests__
```

**What did NOT survive those two deletions — now repaid (2026-09-01).** A code
review caught the first version of this table claiming more than was true, so it
was written out rather than smoothed over. All three are closed; the original
wording is kept below because the *shape* of the mistake is the lesson, not the
fact that it is fixed.

- **The scoping** — `NowRail` queries live rooms, live games and events inside a
  24-hour window, `.in('community_id', joinedIds)`, falling back to Roxy-wide
  only when she has joined nothing. `components/feed/happeningNow.ts` holds the
  scope decision, the window and the ordering as pure functions;
  `__tests__/components/feed/NowRail.test.tsx` fails against the unscoped rail.
- **Live games** — a game with `status = 'live'` in one of her communities now
  has a surface: the same rail. Discover's games rail remains the catalogue.
- **Multi-term business search** — `globalSearch` splits on whitespace and ANDs
  one filter per term across name, description and category. No chip UI came
  back; the prototype's Discover has no per-rail search bar, and `/search` is
  where the design puts lookup.

The original finding, unedited:

- **The scoping.** `HappeningTonightCard` queried `.in('community_id',
  communityIds)` — rooms, events and games *in the communities she had joined*,
  within a 24-hour window. Its replacements are global and unwindowed:
  `useLiveRooms` returns every live room on Roxy, `useEvents` every upcoming
  event with no "tonight" bound. The content is reachable; "what is happening
  tonight, in my communities" is not, and that was the card's whole premise.
- **Live games.** The card joined `community_games` to `games.status = 'live'`.
  Discover's games rail is the catalogue. There is no live-games surface at all.
- **Multi-term business search.** `ChipSearchBar` accumulated search terms as
  chips and ANDed them. `/search` is single-term. Finding a business by name is
  covered; narrowing by two terms at once is not.
  `buildStore.searchChips` is left in place as the state that would back it.

Each is a slice, not a patch. Inventing a half-version of a scoped "tonight"
rail in the parity pass would have been worse than naming the debt.

**Done since:** the e2e suites. All seven Maestro flows now select
`nav-slot-<route>` testIDs instead of dead tab labels, share
`.maestro/subflows/dismiss_first_run.yaml` (the once-a-day Mini Wins modal
swallows the first tap of any flow that navigates), and the onboarding flow goes
through the invite-code gate, which is the real front door. The four Playwright
specs were rewritten against the 3.0 IA and pass 17/17 against the live web
build — the previous versions were failing on `welcome-screen` at `/`, a screen
that stopped being the entry point when the code gate shipped.

Two production bugs came out of running them, neither visible to any unit test:

- **`StreakChip` raced the session.** It fired `record_daily_checkin` on mount
  with no dependency on auth. Feed is the initial tab, so on a cold start the
  RPC could land before the JWT and answer `P0001 not authenticated`;
  `recordDailyCheckin` swallows every failure to `null` and the chip hides. The
  symptom a member sees is a streak that vanishes at random. Now gated on
  `useAuthStore(s => s.user?.id)` and cleared when the user changes.
- **`accessibilityState` is inert on react-native-web 0.19.** Verified in the
  browser: the focused tab rendered `role="tab"` with no `aria-selected`, in
  either state — a tablist where assistive tech cannot tell which tab is
  current, WCAG 2.2 SC 4.1.2. RNW documents flattened `accessibility*` props
  instead of the state object; the one spelling both it and React Native 0.74
  accept is `aria-*`. `lib/a11yState.ts` emits both, and all 25 call sites
  across the app now use it. The Playwright nav smoke asserts the attribute in
  the real DOM, because a unit test cannot see it.

## Known gaps, carried deliberately

- **Ticket tiers.** The prototype shows per-tier pricing; the schema has one
  `events.price_cents` per event and no tiers table. Single-price is the plan.
- **Mute.** The prototype offers mute alongside block; the app has never had
  mute. Block + report + local hide is the whole surface, and the screen should
  say "Blocked" rather than implying a mute exists.
- **Following feed segment.** No follow graph exists, so the segment is backed
  by the friend graph and its empty state says so instead of looking broken.
- **Create sheet: four of five rows are disabled.** Only Post has a composer in
  this app; events, rooms, products and games are authored in Roxy Studio. Each
  row says so rather than opening a "coming soon" toast, because a ＋ button
  that lies is a ＋ button she stops pressing.
- **Second dating-mode writer.** `app/(tabs)/connect/index.tsx` writes
  `profiles.is_dating_mode` directly instead of through
  `profileStore.updateProfile`, so the two paths can disagree. It dies with the
  Connect folder in phase 8; if phase 8 slips, fix the writer on its own.
- **The pink button carries dark ink.** The prototype paints `#FFF8FB` on the
  pink fill, which measures 3.75:1 and fails for a button label. `inkOn()` picks
  `#1A0A2E` at 4.75:1 instead. This is the one deliberate visual departure from
  the design, and it is visible on every primary button.
