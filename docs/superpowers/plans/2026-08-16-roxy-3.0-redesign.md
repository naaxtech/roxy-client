# Roxy 3.0 Redesign — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collapse five nested tabs into Feed / Discover / ＋ / Messages / You, rebuild the feed as a full-bleed vertical pager, unify four profile screens into one shell, and restyle events, rooms and commerce to the 3.0 prototype — with zero feature loss.

**Architecture:** Navigation + UI restructure only. Supabase schema, zustand stores, edge functions and `lib/*` stay as they are; stores gain fields only where the spec needs new state (seller status, saved posts, room hand-raise). Every screen reads colour from `useThemeColors()` and type from `lib/typography.ts` — no literal hex, no literal font size, in any file this plan touches.

**Tech Stack:** Expo 51 · Expo Router v3 · React Native 0.74 · TypeScript strict · zustand · Supabase · `@shopify/flash-list` · `expo-linear-gradient` · `react-native-svg` · Daily.co (guarded) · Stripe Connect Express · jest + @testing-library/react-native · Maestro · Playwright.

**Spec:** `docs/handoff/roxy-3.0/PROMPT.md` and `docs/handoff/roxy-3.0/README.md`.
**Design source of truth:** `docs/handoff/roxy-3.0/Roxy App.dc.html`.

## Global Constraints

Every task's requirements implicitly include this section.

- **Branch:** `redesign/roxy-3.0`. Never commit to `main` or `version2`.
- **Colour:** only `useThemeColors()` keys, `BRAND_GRADIENT`, `LIVE_GRADIENT` and `inkOn()` from `lib/theme.ts`. A literal hex in a new or edited file is a defect. Ink on a brand fill comes from `inkOn(fill)`, never `'#fff'`.
- **Type:** only `TYPE.<step>` from `lib/typography.ts`. A literal `fontSize` is a defect.
- **Radii / motion:** `RADII` and `MOTION` from `lib/theme.ts`. Sheets are `RADII.sheet` top corners, `MOTION.sheet` in and out, `Easing.bezier(...MOTION.bezier)`.
- **Gradient discipline:** `BRAND_GRADIENT` is identity only — wordmark, ＋ button, Roxy FAB. `LIVE_GRADIENT` is live/urgent only. A gradient anywhere else is a defect.
- **LIVE never means colour alone:** every live indicator renders a dot **and** the word.
- **Touch targets:** ≥ `MIN_TOUCH_TARGET` from `lib/touchTargets.ts`, measured, not `hitSlop`.
- **Accessibility:** every icon-only control gets `accessibilityLabel` and `accessibilityRole`.
- **Three states:** every data surface renders loading, empty and error deliberately. A blank list is a defect.
- **No `console.log`.** Use `logError` / `logBreadcrumb` from `lib/errorLogger`, `Analytics` from `lib/analytics`. Never call Sentry or PostHog from a component.
- **PII:** never log email, display name, pronouns, identity labels, city, message or post content. `hashUserId()` before logging any user id.
- **Daily.co:** never a module-level import. Check `provider.isAvailable` and validate shape. Never call `createCallObject()` from a screen.
- **Writes are not renders:** `callEdgeFunction` returns `{data, error}` and does not throw — check `error`. A PostgREST write returns 200 for zero rows — gate any destructive follow-up on `count`. Never toast success over an unchecked write.
- **Feature parity:** nothing is deleted. A screen is moved or merged, never dropped. A route folder is removed only after every screen inside it is reachable from its new home.
- **Per task:** `npx tsc --noEmit` clean, `npx eslint . --ext .ts,.tsx --max-warnings 0` clean, `npx jest --ci` green, then one conventional commit.

## Reality corrections — read before any task

Six read-only mapping passes over the repo (2026-08-16) contradict several
assumptions in `PROMPT.md`. The plan below is written against the repo, not the
brief. Where they disagree, the repo wins and the deviation is noted here.

**Already built — do not rebuild:**
- `components/feed/FeedPager.tsx` is the vertical snap pager, and it is better
  than the brief's suggestion. It uses FlashList with `snapToInterval` +
  `snapToAlignment="start"` + `disableIntervalMomentum` and **deliberately never
  sets `pagingEnabled`** (flash-list#1200 breaks it on Android). Viewability is
  `viewAreaCoveragePercentThreshold: 60`; setting `itemVisiblePercentThreshold`
  as well makes flash-list throw. Page height comes from `onLayout`, never
  `useWindowDimensions()`. Do not "fix" any of this.
- `FeedCell` routes post type → cell; `FeedCellChrome` owns the right action
  rail, author chip, community crest and scrim; `ReelCell`/`PhotoCell`/
  `TextCell`/`PollCell`/`ResourceCell` are the renderers; `FeedSafetySheet` is
  the long-press safety sheet; `FeedVideoPlayer` has a ±1 decoder window.
- `feedChromeTokens.ts` holds the scrim alphas, `RAIL_GUTTER`, `CHROME_BOTTOM`,
  `CREST_SIZE` and caption caps. `__tests__/components/feedChromeContrast.test.ts`
  asserts the composited ratios — changing an alpha there breaks that gate.

**Wrong in the brief:**
- `hooks/useReactions` is the **chat message-reaction** hook. Feed likes go
  through `feedStore.toggleLike(postId)`, and the displayed count must come from
  `displayedLikeCount(post, likeCountDeltas)` in `lib/reels.ts` for any list that
  holds its own rows. Applying the delta to a list rendered straight out of
  `feedStore.posts` double-counts the tap.
- `components/feed/VideoPostCard` / `StaticPostCard` are the **legacy card feed**
  (Connect's `feed` sub-tab), not the pager renderers. Restyle
  `ReelCell`/`PhotoCell`/`TextCell` instead.
- `app/user/[userId].tsx`, `app/community/[id].tsx`, `app/chat/[id].tsx`,
  `app/sister-button.tsx`, `app/speed-dating/*`, `app/communities.tsx` are
  **one-line re-export shims** over the `(tabs)/…` implementations. Renaming a
  tab folder means fixing its shim, not moving the screen.

**Greenfield — these do not exist and need schema, RLS and UI:**
| Feature the brief asks for | What exists today |
|---|---|
| Content warning + tap-to-reveal | Nothing. `posts.is_flagged` exists and is **never read**. Needs a `content_warning text` column. |
| Community channels (`#general`, `#meetups-events`, `#buy-sell-trade`) | Nothing. `conversation_type` is `direct \| speed_date \| sister`; `messages.message_type` has no channel member. `community_rooms` is live A/V, not text. |
| Raise hand · speaker/listener roles · leave quietly | Nothing. The only role is `is_host` (Daily `is_owner`), granting exactly one power: long-press to mute. No `room_participants` table — the DB stores an integer `participant_count`. |
| Consent strip in speed dating | Nothing. The session has a `🤍/❤️` Like toggle, no report, no block, no consent UI. `safetyStore` is not imported by either room screen. |
| Ticket tiers | Nothing. One `events.price_cents` per event. `fee_tiers` is a platform-fee lookup for hosts and is unrelated. |
| Seller approval state machine | Nothing named. Nearest: `businesses.is_verified`, `can_sell`, `stripe_account_id`. `vetting_status` is a **member** field (invite gate), not a seller one. |
| Saved-posts store | No store. `post_saves` is read by `feedStore.savedPostIds` and by `components/profile/SavedPosts.tsx` independently. |
| Mute | No mute anywhere. Block + report + local hide is the whole safety surface. `safetyStore.reportTarget.contentType` is a closed union `'message' \| 'post' \| 'profile'` — reporting a room or a date needs it widened. |

**Migrations are files, not applied state.** Any task here that needs a column
writes a numbered migration under `supabase/migrations/` (next free number —
`ls` first; 091 is the highest today) plus a `_down.sql` in `supabase/downs/`,
and **stops there**. Applying it against production is a human step, and the
feature must degrade honestly until it lands: read the column defensively and
render the pre-migration behaviour when it is absent.

**Divergences accepted, with reasons:**
- Dating mode and ghost mode live on `profiles` (`is_dating_mode`, `is_ghost`)
  and are written through `profileStore.updateProfile`, not `safetyStore`. Task 3
  keeps that and does **not** move them; it fixes the second, divergent writer in
  `app/(tabs)/connect/index.tsx` that bypasses `updateProfile`.
- The brief's "reuse `hooks/useReactions`" for the feed is not followed.
